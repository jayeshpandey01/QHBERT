## Overview

A single ML classifier scoring "real vs. fake" from article text alone
misses several real attack vectors. This verification layer is a pipeline
of four checks, run in order, each catching a different failure mode the
others don't:

```
Article (text + optional image)
    |
    v
1. Is the text AI-generated?
    |
    v
2. Does the image match the text?
    |
    v
3. Is the image AI-generated, given what the text claims?
    |
    v
4. Even if 1-3 all pass: is this actually being reported elsewhere?
   (catches a hacked/compromised legitimate channel posting fabricated
   content that is itself human-written and internally consistent)
    |
    v
Combined verdict
```

Checks 1-3 are content-based (can a machine tell something's off with
this specific text/image). Check 4 is corroboration-based (is the outside
world confirming this happened at all) — it's the only one of the four
that catches a fully "clean" fabrication posted through a compromised
legitimate source, which content analysis alone cannot detect.

---

## 1. AI-generated text detection

**Goal**: estimate the probability the article text was generated by an
LLM rather than written by a human.

**Why it matters**: LLM-generated misinformation can be fluent and
grammatically perfect, defeating classic linguistic-feature-based fake
news detectors (sensationalism index, TTR, etc. from the previous
project) that assume human writing patterns.

**Approaches to evaluate**:
- Classifier-based: fine-tuned RoBERTa detectors (e.g.
  `roberta-base-openai-detector`-style models) — fast, but need
  retraining/fine-tuning as generator models evolve.
- Statistical: perplexity/burstiness under a reference LLM (DetectGPT-style
  zero-shot methods) — no training needed, but weaker on short text and
  on text a human has lightly edited.
- Open question: which generator models to test against (GPT-family,
  Claude, Llama, Gemini) — detectors trained on one family often
  generalize poorly to another.

**Output**: a probability/score, not a hard boolean — feed into the
combined verdict, don't gate on it alone (false positives on
legitimately well-written human journalism are a real risk).

---

## 2. Text-image consistency check

**Goal**: given an article's text and its accompanying image, determine
whether the image actually depicts what the text describes.

**Why it matters**: a real, unmodified photo attached to a false caption
(e.g. an old photo from a different event presented as current) is a
common misinformation pattern that neither pure text analysis nor pure
image-forensics analysis catches alone — the individual pieces are both
"authentic," only the pairing is false.

**Approaches to evaluate**:
- CLIP-style embedding similarity: encode text and image into a shared
  space, score cosine similarity. Cheap, but only captures coarse
  semantic alignment, not specific factual claims (won't catch "same
  type of scene, wrong specific event").
- Vision-language entailment: ask a VLM directly "does this image support
  this caption," which can reason about specifics an embedding similarity
  score can't.
- The previous project already has a CLIP ViT-B/32 pipeline
  ([FINAL_PROJECT_REPORT.md section 4](https://github.com/jayeshpandey01/fake_news) —
  L2-normalized 512-dim embeddings) — reuse/extend that rather than
  building fresh.

**Output**: a match/mismatch score. A clear mismatch is a strong red flag
on its own, independent of whether either the text or image individually
looks suspicious.

---

## 3. AI-generated image detection, conditioned on the text's claim

**Goal**: determine whether the image is synthetic (GAN/diffusion-
generated or manipulated), specifically evaluated against what the text
claims the image shows (e.g. "photo from the scene" implies a real
photograph — if forensics say synthetic, that's a direct contradiction of
the claim, not just a generic "AI image" flag).

**Why it matters**: this is the deepfake/synthetic-media detection half
of misinformation, most damaging as "evidence" precisely because images
carry more perceived credibility than text.

**Approaches to evaluate**:
- The previous project already achieved 97.2% accuracy on GenImage
  (Nature vs. AI) using ResNet-50/CLIP ViT-B/32 — start there rather than
  from scratch.
- Consider whether "conditioned on the text's claim" needs anything
  beyond running the detector and comparing its verdict against what the
  text implies (i.e., claim-checking is really check #2 combined with #3,
  not a separate model) — worth deciding during implementation rather
  than building a third bespoke model.

**Output**: AI-generated probability + explicit flag if it contradicts
what the text claims about the image's authenticity/provenance.

---

## 4. Cross-source corroboration via web search (the compromised-channel case)

**Goal**: even when text and image both pass checks 1-3 (human-written,
internally consistent, no synthetic media detected), verify the story is
independently corroborated by other legitimate sources — because a
compromised/hacked account on an otherwise-legitimate channel can post
fully "clean" fabricated content that no content-based check will ever
catch.

**Design**:
1. Extract the core factual claim(s) from the article.
2. Web-search / query 5-6 major, pre-selected news channels for
   independent coverage of the same event.
   - Needs an explicit, decided-in-advance list of which 5-6 channels
     count as corroborating sources (and why those, and how the list is
     maintained/updated).
   - Needs a decision on search mechanism: live web search API vs. a
     news-specific API (e.g. GDELT, NewsAPI) vs. scraping — each has
     different cost/rate-limit/reliability tradeoffs.
3. **Worst case — no news channel has covered it at all**: fall back to
   searching social media for organic discussion/reaction as weaker,
   auxiliary evidence (e.g., is this trending, are other accounts
   discussing/reacting to it, independent of the original post).
   - This fallback signal is inherently weaker than news corroboration
     and should be weighted accordingly in the final verdict, not treated
     as equivalent confirmation.
4. Timing matters: breaking news may have zero corroboration for the
   first few hours simply because it's new, not because it's fake — the
   system needs to distinguish "not yet corroborated" from "actively
   uncorroborated after a reasonable window," which requires either a
   time-decay in confidence or an explicit "insufficient evidence yet"
   output state rather than forcing a real/fake binary.

**Output**: a corroboration score (news-level, or social-media-fallback
level if no news coverage exists) + explicit confidence/recency state
rather than a forced binary.

---

## Combining the four signals

Not yet designed — needs a decision before implementation on how checks
1-4 aggregate into one verdict. Considerations:
- These are heterogeneous signal types (ML probabilities, a match score,
  a corroboration score with its own confidence state) — a simple average
  is probably wrong.
- Check 4 catching what 1-3 structurally cannot means it likely shouldn't
  be reduced to "one vote among four" — a strong corroboration failure
  arguably should dominate even if 1-3 all look clean, and vice versa a
  strong corroboration pass might reasonably override borderline 1-3
  scores.
- Needs example cases worked through by hand before choosing a
  combination rule, not just implemented from first principles.
